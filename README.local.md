# Qwen Image Studio — локальная сборка для MacBook Pro M1 Max (32 ГБ)

Форк [rigorhormist/QwenStudio](https://github.com/rigorhormist/QwenStudio) (MIT), переделанный для
**Qwen-Image-2.1** на Mac с 32 ГБ общей памяти: веб-интерфейс в браузере, все функции модели,
квантованные веса, переключение официальной/uncensored версии и локальный улучшатель промптов.

## Запуск

```bash
./run.sh            # http://127.0.0.1:8765 — откроется в браузере
```

Первый раз: `./setup.sh` (создаёт `.venv` на Homebrew Python 3.12 и ставит закреплённые версии пакетов),
затем в «Настройки → Файлы модели» нажать «Скачать все недостающие файлы» (~39 ГБ, всё в `data/models`).
Остановить сервер — `Ctrl+C` в терминале. Сервер слушает только `127.0.0.1`, API защищён токеном.

## Что умеет (все функции Qwen-Image-2.1)

Всё управляется промптом и 0–10 референсами (`<image1>…<image10>` в тексте промпта):

- генерация по тексту (1K по умолчанию, 2K — отдельная группа размеров, очень медленно);
- **прозрачные PNG (RGBA)** — переключатель «Прозрачный фон»;
- удаление фона / вырезание объекта (шаблоны);
- правка одной картинки («Продолжить правку» у любого результата);
- **мульти-референс до 10 изображений** (примерка, групповое фото, обстановка комнаты…);
- **локальные правки**: в просмотрщике «Разметить области правки» — круг / рамка / кисть, 5 цветов
  (белая кисть = официальный режим «закраска»), либо **отдельная маска** (белое на чёрном);
- рендер и перевод текста, стилизация, расширение кадра, панорама 360°, реставрация и колоризация,
  замена лица/одежды/фона, эмоция и поза, инфографика — готовые **шаблоны задач** в меню «+»;
- **официальный улучшатель промптов** (PE-T2I / PE-I2I, Qwen3.5-VL 9B, 4-bit MLX) — «Улучшить промпт»;
  он же выбирает пропорции холста («Пропорции → Выбирает улучшатель»);
- негативный промпт + CFG, seed, 1–4 картинки за задачу, очередь, отмена, галерея, превью во время
  генерации, подробности каждой генерации (исходный/улучшенный/фактический промпт, seed, настройки);
- интерфейс на русском, английском и китайском.

## Версия модели и скорость

| Переключатель | Что это |
|---|---|
| Официальная | `unsloth/Qwen-Image-2.1-GGUF` Q8_0 — официальные веса |
| Без цензуры | `abenzerps/Qwen-Image-2.1-Uncensored-GGUF` UC-Q8_0 — изменённые веса (способ изменения не описан) |

| Режим | Шаги | 1024², этот Mac (замеры) |
|---|---|---|
| Турбо | 4 (Viggle turbo LoRA, без CFG) | **≈ 1,5 мин** (85 с: энкодер 17 с + загрузка 19 с + 4 × 10,5 с) |
| Стандарт | 25 | **≈ 6 мин** (356 с, ~10–12 с/шаг с превью) |
| Качество | 40 (официально) | ≈ 8–9 мин |

Правки (12 шагов): 1 референс — 4,2 мин, маска — 4,6 мин, цветная разметка — 4 мин, 5 референсов — 5,5 мин;
правка в «Турбо» — ≈ 2 мин. Улучшатель промптов добавляет ≈ 45–60 с (≈ 52 токена/с на MLX).
2K — в 6–7 раз дольше 1K. Текст модель лучше всего рисует на английском и китайском; кириллица
получается приблизительной, особенно в «Турбо» — для точной надписи берите «Качество» и короткие фразы.
Оценка времени у поля ввода калибруется по реальным замерам (`data/perf.json`).

## Как это устроено (почему влезает в 32 ГБ)

Каждая задача — до трёх **отдельных процессов**, память освобождается при выходе каждого:

1. `enhancer_worker.py` — улучшатель промптов (MLX 4-bit, ~6 ГБ), только если включён;
2. `encode_worker.py` — текстовый энкодер Qwen3-VL-8B (SDNQ int8, ~10 ГБ) → эмбеддинги в `data/cache`
   (повтор с тем же промптом и референсами пропускает этот этап);
3. `worker.py` — трансформер GGUF Q8_0 (7.6 ГБ, fp16) + VAE → латенты; затем трансформер выгружается
   и VAE декодирует в fp16.

Пики MPS (замеры): энкодер ~12 ГБ, генерация 1024² ~14 ГБ, правка с 1–2 референсами ~17–19 ГБ.
Число/разрешение референсов подбирает планировщик: KV-кэш ≈ 2,5 ГБ на референс 1024², бюджет 6 ГБ
(1–2 реф. по 1024 px, 3 — 896, 4 — 768, 5 — 640, 6–9 — 512, 10 — 384). «Полная детализация
референсов» отключает кэш (дольше).

Исправления для Apple Silicon (проверены замерами, `data/spikes/`):

- баг PyTorch MPS ≤ 2.14 в 5-мерном `F.pad` портил кодирование VAE (PSNR 10 dB вместо 42 dB) —
  `mps_patches.py` заменяет его на `torch.cat` (бит-в-бит как на CPU);
- fp16 вместо bf16 (у M1 нет аппаратного bf16): 9,6 с/шаг против 16,3 с; при NaN — автоповтор в bf16;
- полнокадровое декодирование VAE в fp32 требовало +18 ГБ — теперь fp16 (+8,6 ГБ, PSNR 78 dB к fp32);
- `PYTORCH_MPS_HIGH_WATERMARK_RATIO=1.0` в `run.sh`: слишком большая задача завершится понятной
  ошибкой нехватки памяти, а не уведёт систему в swap.

**Совет:** перед генерацией закройте тяжёлые приложения — при правках свободной памяти в системе
остаётся 2–3 ГБ.

## Файлы и настройки

- `data/models` — веса (закреплённые ревизии, SHA-256, `macos/backend/models.json`;
  пересборка манифеста: `python3 scripts/build_manifest.py`);
- `data/images` — все картинки; `data/sessions.sqlite3` — чаты; `data/jobs/*.log` — журналы задач;
- переменные в `run.sh`: `QWEN_STUDIO_PORT`, `QWEN_STUDIO_DTYPE` (`auto`/`fp16`/`bf16`),
  `QWEN_STUDIO_KV_BUDGET_GB` (6), `QWEN_STUDIO_ATTN_BUDGET_MB` (512), `QWEN_STUDIO_THINKING_BUDGET`.
